Codeknit은 컴파일러를 실행하거나 매크로를 평가하거나 프로젝트의 종속성을 로드하지 않고 구문을 추출합니다. 아래 매트릭스는 테스트된 구문을 설명하며, 전체 언어 준수 또는 교차 파일 이름 확인을 보장하지 않습니다.

모든 언어에는 `internal/plugin/api_fidelity_test.go`에 정확한 기본 매개변수/반환 시그니처 단언문이 있습니다. 선언 범위는 `internal/plugin/coverage_test.go` 및 개별 언어 테스트 패키지에서도 확인됩니다.

## 헤더 언어 선택

모든 소스 처리 CLI 명령은 `--header-language c|cpp`를 허용합니다. 이 선택은 `.h` 파일에만 적용됩니다. 다른 확장자는 일반적인 파서를 유지합니다.

```bash
codeknit parse ./src --header-language cpp
codeknit fingerprint ./src --header-language c
codeknit graph analyze ./src --header-language cpp
```

기본값은 `c`로, C 매크로, typedef 및 공용체 추출을 보존합니다. `.h`로 명명된 C++ 헤더에는 `cpp`를 사용하세요. `.hpp` 및 `.hxx`로 명명된 파일은 이미 C++을 사용합니다. 이 선택은 명시적입니다. 두 문법 모두 다른 언어의 구문을 일부 수용할 수 있지만 해당 언어의 전체 구조를 추출하지는 않기 때문입니다.

헤더 가드 및 조건부 분기는 조건을 평가하지 않고 탐색됩니다. 따라서 결과에는 상호 배타적인 분기의 선언이 포함될 수 있습니다. 매크로 확장, 포함 확인 및 빌드 플래그는 적용되지 않습니다. TUI는 `.h` 파일에 대해 기본 C 선택을 사용합니다.

## API 형태 유지

예를 들어, Go:

```go
func Pair(a, b int, rest ...string) (string, error)
```

는 다음을 생성합니다:

```text
Pair(a: int, b: int, rest: ...string) -> (string, error)
```

Go 인터페이스 메서드와 Go/Rust 명명된 필드는 일반 모드와 fingerprint 모드 모두에서 심볼로 나타납니다. 메서드와 필드는 소유 유형을 유지합니다. 중첩된 Rust 모듈은 `service.storage.read`와 같은 자격을 갖춘 이름을 유지하며, 다른 모듈이 동일한 이름의 함수를 선언하더라도 마찬가지입니다.

Rust는 동일한 이름의 필드와 메서드를 허용합니다. 필드 범위 이름은 ID와 포함 엣지를 구분하기 위해 내부적으로 `#field` 접미사를 사용합니다. 표시 이름과 시그니처는 원래 필드 이름을 유지합니다.

Python 시그니처는 주석, 기본값, 스플랫 및 호출 규칙 구분자를 유지합니다. 관례적인 첫 번째 `self` 또는 `cls` 매개변수는 바운드 메서드에서 생략되지만, 자유 함수 또는 정적 메서드에서는 보존됩니다.

여러 줄 시그니처는 JSON에서 소스 줄 바꿈을 유지합니다. SKT는 줄 바꿈을 `\n` 및 `\r`로 이스케이프하여 각 심볼이 하나의 물리적 출력 줄에 유지되도록 합니다.

## 알려진 제한 사항

- 복잡한 C/C++ 포인터, 참조, 배열 및 함수 포인터 선언자는 여전히 불완전한 시그니처를 가질 수 있습니다. 매크로 생성 선언은 확장되지 않습니다.
- TypeScript/JavaScript 생성자 처리 및 일부 선택적, 나머지 또는 구조 분해된 매개변수 형식은 불완전합니다.
- 테스트된 사례 외부의 고급 제네릭 제약 조건 및 유형 형식은 언어별로 다릅니다. 반환 유형은 추론되지 않습니다.
- Rust 매크로는 확장되지 않습니다. 아웃라인 모듈 선언은 기록되지만, 해당 파일은 스캔에 포함되어야 합니다. 튜플 필드, 열거형 변형 세부 정보 및 연관 항목은 부분적으로만 지원됩니다.
- 구문 추출은 동적 디스패치, 오버로드, 가져온 종속성 또는 컴파일러 정밀도의 빌드 구성 의미론을 해결하지 않습니다.
- 부분적인 구문 오류로 인해 선언이 누락될 수 있습니다. 보고된 경고를 검사하고 리팩터링을 적용하기 전에 소스를 확인하세요.

보다 완전한 추출은 심볼 수와 ShortID를 변경합니다. 기존 skeleton 출력을 업그레이드할 때는 이전 출력과 혼합하지 말고 다시 생성하세요.
