title: คำสั่งกราฟ
description: แสดงภาพและวิเคราะห์โครงสร้างของโค้ดเบสด้วยอัลกอริทึมกราฟ
---

codeknit มีคำสั่งกราฟสำหรับแสดงภาพโครงสร้าง วิเคราะห์อัตโนมัติ และรวมกราฟการพึ่งพาปัจจุบันเข้ากับประวัติการเปลี่ยนแปลง Git

## graph show

สร้างการแสดงภาพกราฟ HTML แบบโต้ตอบของโค้ดเบสของคุณ

```bash
codeknit graph show <input-path>
```

คำสั่งนี้จะทำการแยกวิเคราะห์โค้ดเบสของคุณและสร้างไฟล์ HTML ที่สามารถใช้งานได้ด้วยตัวเองพร้อมการแสดงภาพกราฟแบบโต้ตอบ สัญลักษณ์ (ฟังก์ชัน คลาส ประเภท) จะปรากฏเป็นโหนด และความสัมพันธ์ของพวกมัน (การเรียก เนื้อหา การนำไปใช้งาน) จะปรากฏเป็นเส้นเชื่อม การแสดงภาพจะเปิดขึ้นโดยอัตโนมัติในเว็บเบราว์เซอร์เริ่มต้นของคุณ

### Flags

| Flag             | ค่าเริ่มต้น                          | คำอธิบาย                                  |
| ---------------- | -------------------------------- | -------------------------------------------- |
| `-o`, `--output` | `./skeleton/codeknit-graph.html` | เส้นทางไฟล์ HTML เอาต์พุต                        |
| `--collect-test` | `false`                          | รวมไฟล์ทดสอบในการวิเคราะห์               |
| `--workers`      | `NumCPU`                         | จำนวน goroutines การแยกวิเคราะห์สูงสุดพร้อมกัน            |
| `--verbose`      | `false`                          | แสดงข้อมูลความคืบหน้าในระหว่างการประมวลผล |

### ตัวอย่าง

```skt
# Generate default visualization
codeknit graph show ./myproject

# Custom output file
codeknit graph show ./myproject -o graph.html

# Include test files
codeknit graph show ./src --collect-test
```

## graph analyze

เรียกใช้อัลกอริทึมกราฟโครงสร้างบนโค้ดเบสของคุณและสร้างรายงาน `.skt` ที่สามารถอ่านได้โดย LLM ซึ่งมีข้อมูลเชิงลึกเกี่ยวกับคุณภาพโค้ด

```bash
codeknit graph analyze <input-path>
```

คำสั่งนี้จะตรวจจับปัญหาคุณภาพโค้ดทั่วไป เช่น การพึ่งพาแบบวนรอบ สัญลักษณ์ศูนย์กลาง โค้ดที่ไม่ได้ใช้งาน god classes และคอขวดทางสถาปัตยกรรม

### อัลกอริทึม

การวิเคราะห์ประกอบด้วยอัลกอริทึมกราฟโครงสร้าง 22 รายการ:

- การพึ่งพาแบบวนรอบ (Tarjan's SCC)
- การตรวจจับศูนย์กลาง (การเชื่อมโยง fan-in/fan-out สูง)
- การตรวจจับโค้ดกำพร้า (ผู้สมัครโค้ดที่ไม่ได้ใช้งาน)
- การตรวจจับ god class/function (มีเนื้อหามากเกินไป)
- ตัวชี้วัดความไม่เสถียร (Robert C. Martin's Ce/(Ca+Ce))
- โซ่การสืบทอดที่ลึก
- Betweenness centrality (การตรวจจับคอขวด)
- จุดเชื่อมต่อ (จุดเดียวที่ล้มเหลว)
- PageRank (ความสำคัญแบบเรียกซ้ำ)
- Transitive fan-in (ขอบเขตผลกระทบ)
- การจำลองการแพร่กระจายการเปลี่ยนแปลง
- การพึ่งพาแพ็กเกจแบบวงกลม
- การตรวจจับการละเมิดเลเยอร์
- การเข้าถึงได้จากจุดเริ่มต้น
- ส่วนประกอบที่เชื่อมต่อกันอย่างอ่อน
- น้ำหนักการพึ่งพา (ความแข็งแกร่งของการเชื่อมโยงแพ็กเกจ)
- ระยะห่างจาก Main Sequence (สมดุล A+I)
- การตรวจจับ shotgun surgery
- การตรวจจับ feature envy
- การละเมิดการพึ่งพาที่เสถียร
- การละเมิดการแบ่งแยกอินเทอร์เฟซ
- ความลึกของการบรรจุ

### Flags

| Flag                      | ค่าเริ่มต้น                         | คำอธิบาย                                              |
| ------------------------- | ------------------------------- | -------------------------------------------------------- |
| `-o`, `--output`          | `./skeleton/graph_analysis.skt` | เส้นทางไฟล์ `.skt` เอาต์พุต                                  |
| `--collect-test`          | `false`                         | รวมไฟล์ทดสอบในการวิเคราะห์                           |
| `--workers`               | `NumCPU`                        | จำนวน goroutines การแยกวิเคราะห์สูงสุดพร้อมกัน                        |
| `--verbose`               | `false`                         | แสดงข้อมูลความคืบหน้าในระหว่างการประมวลผล             |
| `--fan-threshold`         | `10`                            | ค่า fan-in หรือ fan-out ขั้นต่ำในการระบุสัญลักษณ์ศูนย์กลาง           |
| `--god-threshold`         | `15`                            | จำนวนเส้นเชื่อมเนื้อหาขั้นต่ำในการระบุ god class/function |
| `--max-inheritance-depth` | `5`                             | ระบุโซ่การสืบทอดที่ลึกกว่านี้                 |
| `--top-n`                 | `30`                            | จำกัดส่วนเอาต์พุตที่จัดอันดับ; 0 = ไม่จำกัด                 |
| `--betweenness-threshold` | `0.001`                         | ค่า betweenness centrality ขั้นต่ำที่จะรายงาน           |
| `--propagation-cutoff`    | `0.05`                          | ความน่าจะเป็นขั้นต่ำในการดำเนินการแพร่กระจายการเปลี่ยนแปลง       |

### ตัวอย่าง

```skt
# Run structural analysis with defaults
codeknit graph analyze ./myproject

# Custom output and thresholds
codeknit graph analyze ./myproject -o analysis.skt --fan-threshold 15

# Show more results per section
codeknit graph analyze ./myproject --top-n 50

# Include test files
codeknit graph analyze ./src --collect-test
```

## graph hotspots

จัดอันดับไฟล์ที่มีการเปลี่ยนแปลงบ่อยและมีความสำคัญทางโครงสร้าง:

```bash
codeknit graph hotspots <input-path>
```

คะแนนนี้รวมความถี่ในการคอมมิต การเปลี่ยนแปลงบรรทัด และความใหม่เข้ากับ PageRank ระดับไฟล์, transitive fan-in และ betweenness centrality รายงานยังระบุการเชื่อมโยงชั่วคราวระหว่างไฟล์ที่มีการเปลี่ยนแปลงซ้ำในคอมมิตเดียวกัน

คอมมิตผสานจะถูกยกเว้นโดยค่าเริ่มต้น คอมมิตที่เปลี่ยนแปลงไฟล์มากกว่า 50 ไฟล์ก็จะถูกยกเว้นด้วยเช่นกัน เพื่อไม่ให้การเปลี่ยนแปลงที่สร้างขึ้นโดยอัตโนมัติ การรวมไฟล์จากผู้จำหน่าย หรือการเปลี่ยนแปลงจำนวนมากที่เป็นกลไกบิดเบือนผลลัพธ์

### Flags

| Flag                     | ค่าเริ่มต้น                   | คำอธิบาย                                      |
| ------------------------ | ------------------------- | ------------------------------------------------ |
| `-o`, `--output`         | `./skeleton/hotspots.skt` | เส้นทางไฟล์เอาต์พุต                                 |
| `--format`               | `skt`                     | รูปแบบเอาต์พุต: `skt` หรือ `json`                   |
| `--since`                | `12mo`                    | ช่วงเวลาประวัติ เช่น `180d`, `12mo` หรือ `2y`  |
| `--max-commits`          | `2000`                    | จำนวนคอมมิตสูงสุดที่จะตรวจสอบ                       |
| `--max-files-per-commit` | `50`                      | ยกเว้นคอมมิตที่เปลี่ยนแปลงไฟล์มากกว่านี้              |
| `--min-cochanges`        | `3`                       | จำนวนคอมมิตที่ใช้ร่วมกันขั้นต่ำสำหรับการเชื่อมโยงชั่วคราว     |
| `--top-n`                | `30`                      | จำนวนผลลัพธ์สูงสุดต่อส่วนรายงาน               |
| `--include-merges`       | `false`                   | รวมคอมมิตผสาน                            |
| `--collect-test`         | `false`                   | รวมไฟล์ทดสอบ                               |
| `--workers`              | `NumCPU`                  | จำนวน goroutines การแยกวิเคราะห์สูงสุดพร้อมกัน            |
| `--verbose`              | `false`                   | แสดงข้อมูลความคืบหน้า                       |

### ตัวอย่าง

```bash
# Analyze the last 12 months
codeknit graph hotspots ./myproject

# Analyze two years and emit JSON
codeknit graph hotspots ./myproject --since 2y --format json -o hotspots.json

# Include larger commits and require stronger coupling
codeknit graph hotspots . --max-files-per-commit 100 --min-cochanges 5
```
