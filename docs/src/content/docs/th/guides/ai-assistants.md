ติดตั้งปลั๊กอิน codeknit ใน Claude Code, Codex หรือ Kiro ให้เป็นปัจจุบัน และถามผู้ช่วยเกี่ยวกับโครงสร้างโค้ดและรายการซ้ำ ปลั๊กอินนี้มีทักษะหนึ่งคือ `codeknit` ทักษะนี้จะบอกผู้ช่วยว่าควรเรียกใช้ `codeknit parse`, `codeknit graph analyze` และ `codeknit fingerprint` เมื่อใด และวิธีการอ่านเอาต์พุต `.skt`

คุณไม่จำเป็นต้องติดตั้งไบนารี `codeknit` ด้วยตัวเอง ครั้งแรกที่ทักษะทำงาน จะเรียกใช้ `scripts/install-codeknit.sh` ที่มาพร้อมกับปลั๊กอิน ซึ่งจะทำสิ่งต่อไปนี้:

1. ออกจากการทำงานทันทีหาก `codeknit` มีอยู่แล้วใน `PATH` หรือใน `~/.local/bin`
2. หากไม่มี จะดาวน์โหลด GitHub release ล่าสุดสำหรับระบบปฏิบัติการและสถาปัตยกรรมของคุณ
3. ตรวจสอบการดาวน์โหลดกับ `checksums.txt` ของ release
4. ติดตั้งไบนารีไปยัง `~/.local/bin` และพิมพ์พาธแบบเต็มในบรรทัดสุดท้ายของเอาต์พุต

หาก `~/.local/bin` ไม่อยู่ใน `PATH` ผู้ช่วยจะเรียกใช้ codeknit ด้วยพาธแบบเต็มสำหรับเซสชันที่เหลือ

หากต้องการควบคุมการติดตั้ง ให้ตั้งค่าตัวแปรสภาพแวดล้อมเหล่านี้:

| ตัวแปร | ผลลัพธ์ |
| --- | --- |
| `CODEKNIT_VERSION` | กำหนด release ตายตัว เช่น `0.6.0` |
| `CODEKNIT_INSTALL_DIR` | เปลี่ยนตำแหน่งการติดตั้ง |

หากต้องการติดตั้งไบนารีด้วยตัวเอง โปรดดูที่ [การติดตั้ง](../../installation/)

## การติดตั้งปลั๊กอิน

เลือกส่วนที่ตรงกับผู้ช่วยของคุณ

### Claude Code

รันคำสั่งเหล่านี้ในเชลล์ของคุณ ภายในเซสชัน Claude Code ให้รันคำสั่งเดียวกันเป็น `/plugin ...`

```bash
claude plugin marketplace add awslabs/codeknit --sparse .claude-plugin skills
claude plugin install codeknit@codeknit
```

### Codex

```bash
codex plugin marketplace add awslabs/codeknit --sparse .agents --sparse .codex-plugin --sparse skills
codex plugin add codeknit@codeknit
```

### Kiro IDE

1. เปิดแผง Powers
2. เลือก **Add Custom Power** จากนั้น **Import power from GitHub**
3. ป้อน `https://github.com/awslabs/codeknit`

### Kiro CLI

Kiro CLI ติดตั้งจากพาธในเครื่อง ดังนั้นให้โคลน repository ก่อน:

```bash
git clone --depth 1 --filter=blob:none --sparse https://github.com/awslabs/codeknit ~/.codeknit-power
git -C ~/.codeknit-power sparse-checkout set skills
kiro-cli powers install ~/.codeknit-power
```

### เกี่ยวกับ `--sparse`

ตัวเลือก `--sparse` เป็นตัวเลือกเสริม จะจำกัดการโคลนเฉพาะไฟล์ manifest ของปลั๊กอินและ `skills/` แทนที่จะโคลนทั้งต้นไม้ซอร์สโค้ด

### การติดตั้งทักษะด้วยตนเอง

หากผู้ช่วยของคุณอ่าน Agent Skills แต่ไม่รองรับปลั๊กอิน ให้คัดลอก `skills/codeknit/` ไปยังไดเรกทอรีทักษะสำหรับผู้ช่วยของคุณ:

- `~/.claude/skills/`
- `~/.codex/skills/`
- `~/.kiro/skills/`

## การอัปเดตปลั๊กอิน

| ผู้ช่วย | คำสั่งหรือการดำเนินการ |
| --- | --- |
| Claude Code | `claude plugin marketplace update codeknit` |
| Codex | `codex plugin marketplace upgrade` |
| Kiro IDE | เลือก **Check for updates** ในแผง Powers |
| Kiro CLI | รัน `git -C ~/.codeknit-power pull` จากนั้นรัน `kiro-cli powers install ~/.codeknit-power` อีกครั้ง |

การอัปเดตปลั๊กอินจะไม่อัปเดตไบนารีที่ติดตั้งอยู่แล้ว หากต้องการเปลี่ยนเวอร์ชันของไบนารี ให้ตั้งค่า `CODEKNIT_VERSION` ตามที่อธิบายไว้ข้างต้น

หากคุณอัปเกรด codeknit และการดึงข้อมูลมีการเปลี่ยนแปลง รหัสสัญลักษณ์อาจเปลี่ยนแปลงด้วย ให้ขอให้ผู้ช่วยสร้างเอาต์พุตทั้งหมดใหม่แทนที่จะผสมชิ้นส่วนจากการรันที่ต่างกัน

## สิ่งที่ทักษะสอนให้ผู้ช่วย

ทักษะนี้ให้กฎเหล่านี้แก่ผู้ช่วย เพื่อที่คุณไม่ต้องทำซ้ำในทุกคำขอ:

- **เลือกคำสั่งตามคำถาม**
  - `parse` ตอบคำถามเกี่ยวกับสิ่งที่มีอยู่ ตำแหน่งที่อยู่ และสิ่งที่เรียกใช้ สืบทอด หรือมีอะไรบ้าง
  - `graph analyze` ค้นหาการพึ่งพาแบบวนรอบ ฮับ โค้ดที่ไม่ใช้งาน god classes และคอขวด
  - `fingerprint` ค้นหารายการที่คัดลอกและวางและผู้สมัครในการรีแฟคเตอร์
- **ใช้โหมดเอาต์พุต `directory-flat` เป็นค่าเริ่มต้น** ผู้ช่วยเขียนไฟล์ที่แบ่งเป็นชิ้นไปยัง `./skeleton/` และอ่านเฉพาะชิ้นที่ต้องการเท่านั้น ใช้โหมดเอาต์พุต `inline` เฉพาะกับไฟล์เดียวหรือไฟล์จำนวนน้อยเท่านั้น เนื่องจาก `inline` จะดัมพ์ทุกอย่างลงในหน้าต่างบริบท
- **อ่านเอาต์พุต `.skt` ไม่ใช่ซอร์สดิบ สำหรับคำถามเกี่ยวกับโครงสร้าง** ผู้ช่วยจะเปิดไฟล์ซอร์สเฉพาะเพื่อตรวจสอบหรือเปลี่ยนแปลงรายละเอียดการใช้งาน โดยใช้ช่วงบรรทัดจากเอาต์พุต เอกสาร `references/output-format.md` ของทักษะนี้มีรูปแบบเต็ม โปรดดูที่ [เอกสารอ้างอิงรูปแบบเอาต์พุต](../../reference/output-format/) ด้วย
- **เลือกช่วงความคล้ายคลึงและปฏิบัติต่อการจับคู่เป็นสัญญาณ** fingerprint เปรียบเทียบรูปร่างโครงสร้าง ไม่ใช่เจตนา ผู้ช่วยจะอ่านสัญลักษณ์ทั้งสองของคู่ก่อนที่จะเสนอการรีแฟคเตอร์

## ขอการวิเคราะห์โครงสร้าง

1. ขอให้ผู้ช่วยวิเคราะห์โครงสร้างโค้ดเบสของคุณ ตัวอย่างเช่น: "จัดทำแผนที่โครงสร้างของ `./src` และบอกฉันว่ามอดูลใดบ้างที่ขึ้นอยู่กับแพ็กเกจ auth"
2. ผู้ช่วยจะตรวจสอบให้แน่ใจว่าไบนารีได้รับการติดตั้ง จากนั้นรัน `codeknit parse` พร้อมกับเปิดใช้งานเส้นเชื่อม และอ่านเอาต์พุต `.skt`
3. ถามคำถามติดตามเกี่ยวกับการพึ่งพา โซ่การเรียกใช้ หรือโค้ดที่ไม่ใช้งาน ผู้ช่วยจะตอบจากเอาต์พุต
4. สำหรับการวิเคราะห์เชิงลึก ให้ขอการตรวจสอบโครงสร้าง ตัวอย่างเช่น: "ค้นหาการพึ่งพาแบบวนรอบและ god classes ใน `./src`" ผู้ช่วยจะรัน `codeknit graph analyze` และอ่านรายงาน

ความสัมพันธ์ที่ระบุเป็น `[unresolved]` หรือ `[ambiguous]` ในเอาต์พุตเป็นความไม่แน่นอน ไม่ใช่การพึ่งพาที่ได้รับการยืนยัน ปฏิบัติต่อคำตอบที่อิงกับความสัมพันธ์เหล่านี้เป็นผู้สมัครที่ต้องตรวจสอบ

สำหรับคำสั่งที่อยู่เบื้องหลังคำขอเหล่านี้ โปรดดูที่ [คู่มือคำสั่ง parse](../parse-command/) และ [คู่มือคำสั่งกราฟ](../graph-commands/)

## ขอการตรวจหารายการซ้ำ

1. ขอให้ผู้ช่วยค้นหารหัสที่ซ้ำกัน ตัวอย่างเช่น: "ค้นหาฟังก์ชันที่คัดลอกและวางใน `./src`"
2. ผู้ช่วยจะรัน `codeknit fingerprint` และอ่านส่วน `[duplicates]` ของ `./skeleton/fingerprints.skt`
3. ผู้ช่วยจะเปิดสัญลักษณ์ทั้งสองของแต่ละคู่ที่ถูกทำเครื่องหมาย จากนั้นเสนอการรีแฟคเตอร์
4. หากผลลัพธ์มีสัญญาณรบกวน ให้ขอให้ปรับช่วงความคล้ายคลึงหรือเพิ่มการจัดอันดับใหม่เชิงความหมาย การจัดอันดับใหม่ต้องการเซิร์ฟเวอร์ Ollama ในเครื่องพร้อมโมเดล embedding ที่ดึงมาแล้ว

สำหรับตัวเลือกที่อยู่เบื้องหลังคำขอเหล่านี้ โปรดดูที่ [คู่มือคำสั่ง fingerprint](../fingerprint-command/)

## เคล็ดลับ

- เตือนผู้ช่วยให้อ่านไฟล์ `.skt` ไม่ใช่ซอร์สดิบ สำหรับคำถามเกี่ยวกับโครงสร้าง ซึ่งจะช่วยให้บริบทมีขนาดเล็ก เนื่องจากรูปแบบนี้มีขนาดกะทัดรัดและเก็บสัญลักษณ์ ความสัมพันธ์ และช่วงบรรทัด
- ใช้ `graph analyze` สำหรับข้อมูลเชิงลึกด้านคุณภาพโค้ด ผลการค้นพบเป็นผู้สมัครในการตรวจสอบ เนื่องจากผู้เรียกใช้ภายนอกและการส่งผ่านแบบไดนามิกอาจเปลี่ยนแปลงผลลัพธ์ได้
- รัน fingerprint ก่อนการรีแฟคเตอร์ขนาดใหญ่เพื่อค้นหารายการที่คัดลอกและวางที่ควรจะถูกรวมเข้าด้วยกัน
- หากผู้ช่วยรัน `parse` ใหม่ไปยังไดเรกทอรีที่มีเอาต์พุต `.skt` อยู่แล้ว codeknit จะปฏิเสธการเขียน ให้ขอให้ส่ง `--clean` เพื่อแทนที่เอาต์พุตก่อนหน้า
- หากการดาวน์โหลดไบนารีล้มเหลว (ออฟไลน์หรือแพลตฟอร์มที่ไม่รองรับ) ให้ดาวน์โหลด release ด้วยตนเองจาก [หน้ารีลีส](https://github.com/awslabs/codeknit/releases) หรือดูที่ [การติดตั้ง](../../installation/)
- หากการรันรายงานผลลัพธ์บางส่วน ให้ตรวจสอบ stderr และส่วน `[errors]` ดูรายละเอียดใน [ความน่าเชื่อถือของการวิเคราะห์](../../reference/analysis-reliability/)
