หน้านี้แสดงรายการคำสั่งของ codeknit ทุกคำสั่ง อาร์กิวเมนต์ และแฟล็กทั้งหมด สำหรับคำแนะนำที่เน้นงาน โปรดดูที่ [คู่มือคำสั่ง parse](../../guides/parse-command/), [คู่มือคำสั่ง graph](../../guides/graph-commands/) และ [คู่มือคำสั่ง fingerprint](../../guides/fingerprint-command/)

## สรุปคำสั่ง

| คำสั่ง                                       | วัตถุประสงค์                                                        |
| --------------------------------------------- | -------------------------------------------------------------- |
| `codeknit`                                    | เปิดใช้งาน UI อินเตอร์เฟซแบบ terminal แบบโต้ตอบ                  |
| `codeknit parse <input-path> [output-dir]`    | ดึงสัญลักษณ์และความสัมพันธ์ลงในเอาต์พุต `.skt` หรือ JSON          |
| `codeknit graph show <input-path>`            | สร้างกราฟ HTML แบบโต้ตอบ                                         |
| `codeknit graph analyze <input-path>`         | รันอัลกอริทึมกราฟโครงสร้างและเขียนรายงาน `.skt`                   |
| `codeknit graph hotspots <input-path>`        | จัดอันดับ hotspots การเปลี่ยนแปลงโดยใช้ประวัติ Git และโครงสร้างกราฟ |
| `codeknit fingerprint <input-path>`           | ตรวจจับโค้ดที่ซ้ำและเกือบซ้ำ                                      |
| `codeknit completion <shell>`                 | สร้างสคริปต์เติมคำสั่งสำหรับ shell                                |

คำสั่งที่ประมวลผลซอร์สโค้ดมีทั้งหมด 5 คำสั่ง ได้แก่ `parse`, `graph show`, `graph analyze`, `graph hotspots` และ `fingerprint` คำสั่งเหล่านี้ใช้แฟล็กที่อธิบายไว้ใน [แฟล็กการประมวลผลซอร์สโค้ดที่ใช้ร่วมกัน](#shared-source-processing-flags)

## แฟล็กทั่วไป

| แฟล็ก              | ประเภท | ค่าเริ่มต้น | คำอธิบาย                  |
| ----------------- | ---- | ------- | ---------------------------- |
| `--version`       | bool | `false` | แสดงข้อมูลเวอร์ชัน          |
| `-h`, `--help`    | bool | `false` | แสดงความช่วยเหลือสำหรับคำสั่ง |

## แฟล็กการประมวลผลซอร์สโค้ดที่ใช้ร่วมกัน

แฟล็กเหล่านี้ปรากฏในตารางของแต่ละคำสั่งที่ประมวลผลซอร์สโค้ด

| แฟล็ก                    | ประเภท                | ค่าเริ่มต้น               | ค่าที่อนุญาต       | คำอธิบาย                                                                          |
| ----------------------- | ------------------- | --------------------- | -------------------- | ------------------------------------------------------------------------------------ |
| `--header-language`     | string              | `c`                   | `c`, `cpp`           | Parser ที่ใช้สำหรับไฟล์ `.h`                                                          |
| `--include GLOB`        | string, repeatable  | ทุกซอร์สที่รองรับ       | Gitignore-style glob | รวมเส้นทางซอร์สที่ตรงกัน หลายรูปแบบจะรวมกันเป็น union                                |
| `--exclude GLOB`        | string, repeatable  | ไม่มี                  | Gitignore-style glob | ไม่รวมเส้นทางหรือไดเรกทอรีที่ตรงกัน                                                   |
| `--max-file-size BYTES` | int                 | `10485760` (10 MiB)   | `0` หรือมากกว่า       | ข้ามไฟล์ซอร์สที่มีขนาดใหญ่กว่านี้ `0` จะปิดการจำกัดขนาด                              |
| `--strict`              | bool                | `false`               | —                    | ล้มเหลวก่อนที่จะเขียนเอาต์พุตหากเกิดการสแกนหรือวินิจฉัยการแยกวิเคราะห์                |

### `--header-language`

ใช้กับไฟล์ `.h` เท่านั้น ส่วนขยายอื่นๆ จะใช้ parser ปกติ (`.hpp` และ `.hxx` ใช้ C++ อยู่แล้ว)

- `c` (ค่าเริ่มต้น) รักษาการแยกวิเคราะห์ macro, typedef และ union ของ C
- `cpp` เลือก parser ของ C++ ใช้สำหรับโปรเจ็กต์ C++ ที่มีไฟล์ส่วนหัวชื่อ `.h`

TUI ใช้การเลือก `c` เป็นค่าเริ่มต้นสำหรับไฟล์ `.h`

```bash
codeknit parse ./src --header-language cpp
```

สำหรับความสามารถในการแยกวิเคราะห์ที่ผ่านการทดสอบและข้อจำกัดที่ทราบต่อภาษา โปรดดูที่ [การรองรับภาษาและความเที่ยงตรงของ API](../language-support/) หน้านั้นอธิบายโครงสร้างที่ผ่านการทดสอบ ไม่ใช่การครอบคลุมภาษาหรือความหมายของคอมไพเลอร์ทั้งหมด

### การเลือกซอร์ส

- รูปแบบใช้ glob แบบ gitignore ที่คั่นด้วยเครื่องหมายทับ เทียบกับไดเรกทอรีอินพุต สำหรับอินพุตไฟล์เดียว รูปแบบจะตรงกับชื่อฐานของไฟล์
- ใส่เครื่องหมายคำพูดครอบรูปแบบเพื่อไม่ให้ shell ขยายรูปแบบ
- การยกเว้นมีความสำคัญมากกว่าการรวม
- การรวมไม่ได้ลบล้างกฎ `.gitignore` การกรองไฟล์ทดสอบ หรือการยกเว้นในตัว
- รูปแบบปฏิเสธ (`!pattern`) ไม่ได้รับการยอมรับใน `--include` หรือ `--exclude`
- การสแกนไดเรกทอรีให้ความสำคัญกับไฟล์ `.gitignore` ที่อยู่ในระดับบนและระดับล่างโดยไม่ขึ้นกับไดเรกทอรีการทำงานปัจจุบัน
- การเลือกไฟล์ซอร์สปกติอย่างชัดเจนจะข้ามการกรอง ignore และ test การรวม การยกเว้น และขีดจำกัดขนาดยังคงมีผล
- ไฟล์ทดสอบจะถูกยกเว้นเว้นแต่จะตั้ง `--collect-test`

```bash
codeknit parse ./src --include '**/*.go' --exclude '**/generated/' --strict
```

### การวินิจฉัยและ `--strict`

- Symlink, symlink ของไดเรกทอรี และไฟล์ที่ไม่ใช่ไฟล์ปกติจะถูกข้ามและรายงาน
- เส้นทางที่ไม่สามารถอ่านได้ การอ่านไฟล์ ignore ล้มเหลว ซอร์สที่มีขนาดใหญ่เกินไป และคำเตือนด้านไวยากรณ์ทำให้การวิเคราะห์ไม่สมบูรณ์
- โดยค่าเริ่มต้น ผลลัพธ์บางส่วนที่ใช้งานได้จะถูกเก็บไว้ การวินิจฉัยจะปรากฏบน stderr `parse` ยังบันทึกไว้ใน JSON `errors` หรือใน SKT `[errors]`
- เมื่อใช้ `--strict` การวิเคราะห์ที่ไม่สมบูรณ์จะถูกปฏิเสธก่อนที่จะเขียนเอาต์พุต
- การรันที่ไม่มีซอร์สที่รองรับที่ถูกเลือก หรือการที่ทุกการอ่านซอร์สล้มเหลว จะออกจากระบบโดยไม่สำเร็จเสมอ
- TUI ใช้นโยบาย symlink เดียวกันและค่าเริ่มต้น 10 MiB ฟอร์มของ TUI ไม่เปิดเผยแฟล็กการเลือกและ strict

ดู [ความน่าเชื่อถือของการวิเคราะห์](../analysis-reliability/) สำหรับการรับประกันที่แน่นอน

## `codeknit`

```bash
codeknit
```

การรัน `codeknit` โดยไม่มีคำสั่งย่อยจะเปิดใช้งาน UI อินเตอร์เฟซแบบ terminal แบบโต้ตอบ UI นี้มีคำสั่ง `parse`, `graph show`, `graph analyze`, `graph hotspots` และ `fingerprint` พร้อมกับตัวเลือกของคำสั่งเหล่านั้น

## `codeknit parse`

```bash
codeknit parse <input-path> [output-dir]
```

| -------------- | -------- | ------------ | ------------------------------------------------------------------------ |
| `input-path`   | ใช่      | —            | ไดเรกทอรีซอร์สหรือไฟล์ซอร์สเดียว                                          |
| `output-dir`   | ไม่      | `./skeleton` | ไดเรกทอรีเอาต์พุต ไม่ได้ใช้เมื่อ `--output-mode` เป็น `inline`             |

| แฟล็ก                    | ประเภท                | ค่าเริ่มต้น            | ค่าที่อนุญาต                                   | คำอธิบาย                                                                                         |

| `--format`              | string              | `skt`              | `skt`, `json`                                    | รูปแบบเอาต์พุต                                                                                      |

| `--workers`             | int                 | `0` (`NumCPU`)     | `0` หรือมากกว่า                                   | จำนวนสูงสุดของ goroutines การแยกวิเคราะห์พร้อมกัน                                                 |
| `--verbose`             | bool                | `false`            | —                                                | แสดงข้อมูลความคืบหน้า                                                                             |
| `--header-language`     | string              | `c`                | `c`, `cpp`                                       | Parser ที่ใช้สำหรับไฟล์ `.h`                                                                        |
| `--include GLOB`        | string, repeatable  | ทุกซอร์สที่รองรับ   | —                                                | รวมเส้นทางซอร์สที่ตรงกัน                                                                           |
| `--exclude GLOB`        | string, repeatable  | ไม่มี              | —                                                | ไม่รวมเส้นทางหรือไดเรกทอรีที่ตรงกัน                                                                |
| `--max-file-size BYTES` | int                 | `10485760`         | `0` ปิดการจำกัดขนาด                              | ข้ามไฟล์ซอร์สที่มีขนาดใหญ่กว่า                                                                      |
| `--strict`              | bool                | `false`            | —                                                | ล้มเหลวก่อนเขียนเอาต์พุตหากเกิดการสแกนหรือวินิจฉัยการแยกวิเคราะห์                                   |

### โหมดเอาต์พุต

| ค่า             | พฤติกรรม                                                                                         |
| ----------------- | ------------------------------------------------------------------------------------------------ |
| `inline`          | เขียนไปยัง stdout ไม่ได้ใช้ไดเรกทอรีเอาต์พุต                                                      |
| `directory-flat`  | เขียนไฟล์ที่แบ่งเป็นชิ้นไปยังไดเรกทอรีเอาต์พุต บล็อกซอร์สจะคงสภาพเดิม ดังนั้น `--max-lines` จึงเป็นเป้าหมายการแบ่งแทนที่จะเป็นขีดจำกัดแบบ hard |
| `directory-tree`  | สร้างสำเนาต้นไม้ซอร์ส ชื่อจะคงสกุลของซอร์ส (`foo.c.skt`, `foo.h.skt`) ไฟล์ที่แบ่งจะใช้ `foo.c_part1.skt` |

### พฤติกรรมเอาต์พุต

- หากไม่มี `--clean` เอาต์พุตที่สร้างขึ้นก่อนหน้าสำหรับรูปแบบที่เลือกในไดเรกทอรีเอาต์พุตจะทำให้เกิดข้อผิดพลาด
- เมื่อใช้ `--clean` ไฟล์ `.skt` ที่ล้าสมัย (รูปแบบ SKT) หรือ `codeknit.json` (รูปแบบ JSON) จะถูกแทนที่หลังจากการสร้างสำเร็จเท่านั้น รายการที่ไม่เกี่ยวข้องจะถูกเก็บรักษาไว้
- ในรูปแบบ JSON โหมดไดเรกทอรีจะเขียน `codeknit.json` JSON เป็นเอกสารเดียวและไม่ได้แบ่งตามจำนวนบรรทัด
- `dict.skt` และ `warnings.skt` เป็นชื่อไฟล์เสริมที่สงวนไว้
- ห้ามใช้ไดเรกทอรีซอร์สหรือไดเรกทอรีบรรพบุรุษใดๆ เป็นไดเรกทอรีเอาต์พุต

ดู [โหมดเอาต์พุต](../../guides/output-modes/) และ [คู่มืออ้างอิงรูปแบบเอาต์พุต](../output-format/) สำหรับรายละเอียด

```bash
codeknit parse ./src
codeknit parse ./src ./out --output-mode directory-tree
codeknit parse ./src --output-mode inline --format json --edges
```

| `--fan-threshold`          | int                 | `10`                               | —                       | จำนวนขั้นต่ำของ fan-in หรือ fan-out ที่จะระบุสัญลักษณ์ hub    |
| `--god-threshold`          | int                 | `15`                               | —                       | จำนวนขั้นต่ำของ `contains` เส้นเชื่อมที่จะระบุ god class หรือฟังก์ชัน |
| `--max-inheritance-depth`  | int                 | `5`                                | —                       | ระบุสายการสืบทอดที่ลึกกว่าค่านี้                             |
| `--top-n`                  | int                 | `30`                               | `0` = ไม่มีขีดจำกัด     | จำกัดส่วนเอาต์พุตที่จัดอันดับ                                 |
| `--betweenness-threshold`  | float               | `0.001`                            | —                       | ค่าความสำคัญระหว่างness ขั้นต่ำที่จะรายงาน                   |
| `--propagation-cutoff`     | float               | `0.05`                             | —                       | ความน่าจะเป็นขั้นต่ำที่จะดำเนินการแพร่กระจายการเปลี่ยนแปลง    |
| `--header-language`        | string              | `c`                                | `c`, `cpp`              | Parser ที่ใช้สำหรับไฟล์ `.h`                                 |
| `--include GLOB`           | string, repeatable  | ทุกซอร์สที่รองรับ                  | —                       | รวมเส้นทางซอร์สที่ตรงกัน                                     |
| `--exclude GLOB`           | string, repeatable  | ไม่มี                              | —                       | ไม่รวมเส้นทางหรือไดเรกทอรีที่ตรงกัน                          |
| `--max-file-size BYTES`    | int                 | `10485760`                         | `0` ปิดการจำกัดขนาด    | ข้ามไฟล์ซอร์สที่มีขนาดใหญ่กว่า                                |
| `--strict`                 | bool                | `false`                            | —                       | ล้มเหลวก่อนเขียนเอาต์พุตหากเกิดการสแกนหรือวินิจฉัยการแยกวิเคราะห์ |

การวัดการพึ่งพาจะไม่รวมความสัมพันธ์ที่ไม่แน่นอนและข้อมูลเมตาไฟล์/รวม รายงานจะบันทึกจำนวนความสัมพันธ์ที่ถูกยกเว้น

```bash
codeknit graph analyze ./src -o analysis.skt --fan-threshold 15 --top-n 50
```

### ช่วงความคล้ายคลึง

ช่วงเริ่มต้น 65–95% จะไม่รวมการจับคู่ 100% ในการรายงานการจับคู่โทเค็นที่ปรับให้เป็นบรรทัดฐานที่ตรงกันทั้งหมด ให้ตั้งค่าขอบเขตทั้งสองเป็น `100`:

```bash
codeknit fingerprint ./src --min-similarity 100 --max-similarity 100
```

ผู้สมัครที่มีโทเค็นที่ปรับให้เป็นบรรทัดฐานตรงกันทั้งหมดจะสมบูรณ์ เมื่อมีสัญลักษณ์ที่มีสิทธิ์ตั้งแต่ 500 ขึ้นไป ผู้สมัครรายการที่เกือบซ้ำอื่นๆ จะใช้การดึงข้อมูลเพื่อนบ้าน top-50 โดยประมาณ `--rerank` สามารถลบผู้สมัครที่มีโครงสร้างตรงกันทั้งหมดได้ ดู [ความน่าเชื่อถือของการวิเคราะห์](../analysis-reliability/#duplicate-detection-guarantees) สำหรับรายละเอียด
