1. Overview: codeknit ships as a plugin for Claude Code, Codex, and Kiro containing one skill, `codeknit`, that teaches the assistant to choose between codeknit parse (structure), codeknit graph analyze (structural issues), and codeknit fingerprint (duplicate detection), and to read the .skt output. Users do not install the binary themselves: on first use the skill runs its bundled scripts/install-codeknit.sh, which downloads the latest GitHub release for the platform, verifies it against the release checksums.txt, installs it to ~/.local/bin, and prints the binary path. CODEKNIT_VERSION pins a release; CODEKNIT_INSTALL_DIR changes the location.

2. Installation (one subsection per assistant, commands verbatim):

   Claude Code (shell, or /plugin ... inside a session):
   claude plugin marketplace add awslabs/codeknit --sparse .claude-plugin skills
   claude plugin install codeknit@codeknit

   Codex:
   codex plugin marketplace add awslabs/codeknit --sparse .agents --sparse .codex-plugin --sparse skills
   codex plugin add codeknit@codeknit

   Kiro IDE: Powers panel → Add Custom Power → Import power from GitHub → https://github.com/awslabs/codeknit

   Kiro CLI (installs from a local path):
   git clone --depth 1 --filter=blob:none --sparse https://github.com/awslabs/codeknit ~/.codeknit-power
   git -C ~/.codeknit-power sparse-checkout set skills
   kiro-cli powers install ~/.codeknit-power

   Explain that --sparse is optional and limits the clone to the plugin manifests and skills/. Updating: claude plugin marketplace update codeknit; codex plugin marketplace upgrade; Kiro "Check for updates"; or git pull and re-run kiro-cli powers install.

   Manual fallback: copy skills/codeknit/ into ~/.claude/skills/, ~/.codex/skills/, or ~/.kiro/skills/.

3. What the skill teaches the assistant:
   - Pick the command by question: parse for "what exists / what calls what", graph analyze for cycles, hubs, dead code, god classes, fingerprint for copy-paste and refactor candidates
   - Default to directory-flat output and read chunks selectively; use inline only for single files
   - Read .skt output instead of raw source for structural questions; references/output-format.md holds the full format
   - Choose fingerprint similarity ranges and treat matches as signals (structural shape, not semantic intent)

4. Workflow examples:

   Structural analysis:
   - Ask the assistant to analyze your codebase structure
   - It runs codeknit parse and reads the .skt output
   - It can then answer structural questions: dependencies, call chains, dead code
   - For deeper analysis, it can run codeknit graph analyze

   Duplicate detection:
   - Ask the assistant to find duplicated code
   - It runs codeknit fingerprint and reads the [duplicates] section
   - It investigates flagged pairs and proposes refactors

5. Tips:
   - The assistant should read .skt files, not raw source, for structural questions
   - Use graph analyze for code quality insights
   - Use fingerprint before a large refactor to spot copy-paste that should be consolidated
   - The .skt format is designed to be token-efficient for LLM context windows
